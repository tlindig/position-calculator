# Contributing

## Important notes

Please don't edit files in the `dist` subdirectory as they are generated by `npm run build`. You'll find source code in the `src` subdirectory!

### Code style

[Prettier](https://prettier.io) formats the code, [ESLint](https://eslint.org) checks it, and `.editorconfig` holds the indentation and line endings (LF). Run `npm run format` and `npm run lint` before you commit. `npm run format:check` only reports. `test/reference/` is the frozen jQuery 1.9.0 oracle of the tests. It is excluded from both tools and never changes.

### Tests

`npm test` runs the test pages `test/position-calculator.html` (development set) and `test/validation.html` (generated scenes) in headless Chrome. They need real layout, so a DOM emulation like jsdom does not work. Opened directly in a browser the pages show no output, only `test/run.js` reads the results.

`npm run test:node` checks the import without a DOM and `npm run test:types` checks the type declarations. `npm run test:consumer` packs the package, installs the tarball in a temporary project and loads it with esbuild, Node and `tsc` (offline, a few seconds). Results that are wrong but known are printed as `known`. `npm run test:cross-browser` opens the same pages in Firefox and WebKit with Playwright. It needs `npx playwright install firefox webkit` once.

## Modifying the code

First, ensure that you have [Node.js](http://nodejs.org/) 24 or newer and Chrome installed.

1. Fork and clone the repo.
1. Run `npm ci` to install the dev dependencies.
1. Run `npm test` to check that everything passes.

Just be sure to run `npm test` after making any changes, to ensure that nothing is broken. `npm run build` followed by `npm run test:dist` checks the built files in `dist`. The CI workflow (`.github/workflows/ci.yml`) runs the same commands.

## Submitting pull requests

1. Create a new branch, please don't work in your `master` branch directly.
1. Add failing tests for the change you want to make. Run `npm test` to see the tests fail.
1. Fix stuff.
1. Run `npm test` to see if the tests pass. Repeat steps 2-4 until done.
1. Update the documentation to reflect any changes.
1. Push to your fork and submit a pull request.
